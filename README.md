## The Manifesto

The Electronic Lab Notebook was a mistake.

It took a 19th-century object, the bound paper notebook, and put it behind
glass. Then it charged you per seat, per year, forever, for the privilege. Your
experiments became *pages*. Your instrument output became *attachments*. Your
lineage became *hyperlinks someone forgot to add*. Your data became a hostage,
recoverable only through an "export module" sold separately.

We spent two decades digitising the form of the notebook and none of its
function. The result:

- **Paper-on-glass.** Rich-text pages that a human can read and a machine
  can't reason about. You can't query "every dataset downstream of reagent lot
  2291" because nothing ever recorded that relationship as data.
- **Compliance as a cost centre.** Audit trails bolted on at the application
  layer, verifiable only by trusting the vendor who wrote them.
- **Proprietary blob prisons.** Your results stored in formats only one
  company's software can open, so leaving costs more than staying.
- **Seat-based extortion.** Pricing that punishes you for adding the
  technician, the collaborator, the CRO, or the robot.
- **Instruments as afterthoughts.** A plate reader generating 10⁶ points an
  hour, and the "integration" is a human dragging a CSV into a page.

Software engineers solved every one of these problems years ago. We have
version control, directed graphs, append-only logs, open file formats, and
APIs. Scientists were sold a notebook instead.

**LabRat is a Laboratory Development Environment (LDE)**: what the ELN should
have been. An API-first execution engine for scientific work, with
graph-structured lineage, streaming instrument ingest, a cryptographically
self-verifying audit chain, and open formats all the way down. It ships as one
static binary. It's open source. It has no seat count.

> An IDE didn't digitise the typewriter. It gave programmers a compiler, a
> debugger and version control. An LDE does the same for the bench.

## Core Pillars

### 1 · Lineage over Pages

Experiments are **directed acyclic graphs**, not documents. Every sample,
reagent lot, protocol, run, instrument, dataset and analysis is a node. Every
"used", "generated by" and "derived from" is a typed edge from the
[W3C PROV](https://www.w3.org/TR/prov-o/) ontology.

```
 sample:Plasma-042 ──used──┐
                           ▼
 reagent:SYBR-2291 ──used──► run:qPCR-plate-7 ──wasGeneratedBy──► dataset:raw-Cq
                                                                       │
                                                         used          ▼
                                       dataset:ΔΔCt ◄──wasGeneratedBy── analysis:ddct
```

- **Acyclicity is a database invariant**, enforced by trigger, not a convention.
- *"Where did this number come from?"* is one call:
  `GET /v1/lineage/{id}?direction=upstream`.
- *"What did this contaminated lot touch?"* is the same call, the other way:
  `?direction=downstream`. Recall blast radius in milliseconds.

Protocols are **code**: Markdown with YAML frontmatter. Diffable, reviewable in
a pull request, readable in fifty years without us.

### 2 · Compliance at the Engine Layer

Every mutation writes an audit event **in the same transaction** as the change
it records. Events form a per-tenant **SHA-256 hash chain**: each one commits
to its predecessor, so altering, deleting or reordering any record breaks
every hash after it.

The chain isn't stored *in* PostgreSQL. It is **enforced by** PostgreSQL:

| Guarantee | Mechanism |
|---|---|
| Can't forge an event | Insert trigger recomputes the digest in PL/pgSQL and rejects mismatches |
| Can't fork or skip | Trigger requires `seq = head + 1` and `prev_hash = head.hash` |
| Can't backdate | Timestamps come from the DB clock; trigger rejects anything not current |
| Can't edit or delete | `UPDATE`/`DELETE`/`TRUNCATE` rejected by trigger for *every* role, and never granted |
| Can't see other tenants | Row-Level Security, `FORCE`d, fail-closed when no tenant is set |
| Can't sign without meaning | Signing requires a stated meaning (§11.50), bound into the hash |
| Can't edit a signed run | Trigger seals the row; corrections are new, linked runs |

And it's **self-verifying three ways**, which must agree:

```bash
curl localhost:8080/v1/audit/verify ...           # Go engine + PL/pgSQL, side by side
psql -c "SELECT * FROM audit_verify_chain('…')"   # plain SQL
python3 tools/verify_audit.py chain.ndjson        # offline, stdlib only, zero shared code
```

The digest format is a [public, ~1-page spec](docs/audit-chain.md) with a
pinned test vector. Your auditor doesn't have to trust us. That's the point.

> **What "Part 11 ready" means here.** No software is "Part 11 compliant" on
> its own; compliance is a property of a *validated system* operated under
> *procedures*. LabRat provides the technical controls (§11.10(e) audit
> trails, §11.10(c) record protection, §11.10(f) sequencing, §11.50 signature
> manifestation, §11.70 signature/record linking) at the engine layer, so
> your validation effort tests invariants instead of UI screens. See
> [Status](#status) for the controls still in flight.

### 3 · Data Sovereignty

Your data is yours, in formats that will outlive every vendor, including us.
Every format at a boundary has a public spec; nothing is stored as an opaque
blob.

| Data | Format today | Read it with |
|---|---|---|
| Protocols | **Markdown + YAML frontmatter** | any text editor, git, your eyes |
| Instrument input | **NDJSON** over HTTP | anything that writes JSON lines |
| Lineage | **JSON** over the API, W3C PROV relation names | any HTTP client |
| Audit trail | **NDJSON** + public digest spec | `tools/verify_audit.py`, `jq`, anything |
| Everything | **PostgreSQL** | `pg_dump`. That's it. |

Bulk export formats (columnar, linked data) and archival storage are open
architecture decisions. Each will arrive through its own spec.

No proprietary blobs. No export module. No exit fee. `pg_dump` is your
migration plan.

### 4 · Instrument First

Instruments are first-class producers, not attachments.

```bash
curl --data-binary @run.ndjson -H 'Content-Type: application/x-ndjson' \
     "localhost:8080/v1/instruments/$HPLC/stream?run_id=$RUN"
```

- **NDJSON streaming**: any instrument PC that can run `curl`, Python or a
  LabVIEW HTTP VI can integrate. No driver, no SDK, no middleware licence.
- **Batched array inserts** keep throughput high under Row-Level Security.
- Each upload is **atomic**, becomes a `dataset` lineage node attributed to
  the instrument and generated by the run, and its audit event pins the
  **SHA-256 of the exact bytes received**: chain of custody from the wire.

Built for HPLC chromatograms, qPCR amplification curves, plate readers,
liquid handlers, and whatever your automation cell emits next.

**Design rules**

1. **The UI is core; the API is its only door.** Scientists work in the web
   UI, and it gets no endpoint the API doesn't have.
2. **Invariants live in the database.** If it must never happen, a constraint
   or trigger forbids it, not an `if` statement in a handler.
3. **One binary.** Migrations are embedded; the binary *is* the schema
   version. No sidecars, no JVM, no "platform team required".
4. **Roll forward only.** No down-migrations. Regulated systems don't un-happen.
5. **Open formats at every boundary.** If data leaves, it leaves in a format
   with a public spec.

## Quickstart

**Prerequisites:** Go 1.22+, Docker. (`jq` for the walkthrough.)

```bash
git clone https://github.com/Accelerate-Biotech/LabRatLDE.git
cd LabRatLDE
docker compose up -d                 # PostgreSQL 16
go run cmd/server/main.go            # migrates, seeds a dev tenant, listens on :8080
```

```bash
curl -s localhost:8080/healthz       # {"status":"ok"}
```

> Prefer containers end to end? `docker compose --profile full up -d --build`.

### Walkthrough: sample → run → instrument stream → signature → proof

```bash
T=00000000-0000-4000-8000-000000000001     # seeded dev tenant
H=(-H "X-LDE-Tenant: $T" -H "X-LDE-Actor: you@lab.example" -H "Content-Type: application/json")
API=localhost:8080/v1

# 1. Protocol-as-code: Markdown + YAML frontmatter
EXP=$(jq -Rs '{slug:"il6-qpcr", title:"IL-6 expression, LPS challenge", protocol_md:.}' \
        examples/protocols/qpcr-ddct.md | curl -s "${H[@]}" $API/experiments -d @- | jq -r .id)

# 2. A physical sample enters the graph
SAMPLE=$(curl -s "${H[@]}" $API/lineage/nodes \
           -d '{"kind":"sample","label":"Plasma 042","attrs":{"donor":"D-17"}}' | jq -r .id)

# 3. A run that uses it
RUN=$(curl -s "${H[@]}" $API/runs \
        -d "{\"experiment_id\":\"$EXP\",\"label\":\"Plate 7\",\"inputs\":[\"$SAMPLE\"]}" | jq -r .id)
curl -s "${H[@]}" $API/runs/$RUN/transitions -d '{"to":"running"}' | jq .state

# 4. An instrument streams straight into the run
HPLC=$(curl -s "${H[@]}" $API/instruments -d '{"name":"HPLC-01","kind":"hplc"}' | jq -r .id)
curl -s -H "X-LDE-Tenant: $T" -H "X-LDE-Actor: hplc-01@lab.example" \
     -H 'Content-Type: application/x-ndjson' --data-binary @examples/streams/hplc-uv.ndjson \
     "$API/instruments/$HPLC/stream?run_id=$RUN" | jq

# 5. Complete and sign. The signature meaning is bound into the audit hash.
curl -s "${H[@]}" $API/runs/$RUN/transitions -d '{"to":"completed"}' | jq .state
curl -s "${H[@]}" $API/runs/$RUN/transitions -d '{"to":"signed","reason":"approved"}' | jq .state
curl -s "${H[@]}" $API/runs/$RUN/transitions -d '{"to":"running"}'   # 409: signed runs are sealed

# 6. Full lineage around the run: sample in, instrument dataset out
NODE=$(curl -s "${H[@]}" $API/runs/$RUN | jq -r .node_id)
curl -s "${H[@]}" "$API/lineage/$NODE?direction=both" | jq

# 7. Prove nothing was tampered with, three independent ways
curl -s "${H[@]}" $API/audit/verify | jq '{valid, agree, events: .engine.events}'
docker compose exec postgres psql -U lde -c "SELECT * FROM audit_verify_chain('$T')"
curl -s "${H[@]}" $API/audit/export.ndjson > chain.ndjson && python3 tools/verify_audit.py chain.ndjson
```

### Developer loop

```bash
make test               # unit tests, no database needed
make test-integration   # + database-enforced guarantees (forgery, append-only, RLS)
make build              # ./bin/labrat, static, CGO-free
make image              # distroless/static container, nonroot
```

Configuration is environment-only; see [`.env.example`](.env.example).

## API

| Method | Path | Purpose |
|---|---|---|
| `GET`  | `/healthz` | Liveness + database ping |
| `POST` | `/v1/experiments` | Create an experiment from a Markdown+YAML protocol |
| `GET`  | `/v1/experiments/{id}` | Fetch experiment and parsed protocol metadata |
| `POST` | `/v1/runs` | Start a run; link its inputs with `prov:used` |
| `GET`  | `/v1/runs/{id}` | Fetch run state |
| `POST` | `/v1/runs/{id}/transitions` | Advance the state machine; `signed` requires a meaning |
| `POST` | `/v1/lineage/nodes` | Add a sample, reagent, dataset, … |
| `POST` | `/v1/lineage/edges` | Link nodes (cycles → `409`) |
| `GET`  | `/v1/lineage/{id}` | Provenance closure; `?direction=upstream\|downstream\|both` |
| `POST` | `/v1/instruments` | Register an instrument |
| `POST` | `/v1/instruments/{id}/stream` | NDJSON ingest; `?run_id=` links the dataset to a run |
| `GET`  | `/v1/audit/events` | Page the chain; `?after=<seq>&limit=<n>` |
| `GET`  | `/v1/audit/export.ndjson` | Full chain for offline verification |
| `GET`  | `/v1/audit/verify` | Engine + database verification, side by side |

Run lifecycle:

```
planned ──► running ◄──► paused
running ──► completed | failed ──► signed     (signed is terminal and sealed)
planned | running | paused ──► aborted        (requires a reason)
```

## Contributing

Bench scientists, lab automation engineers, QA/CSV folks, and Go developers
are all equally welcome. The best issues start with *"at the bench, I need
to…"*.

- **Specs first.** Every change traces to an EARS requirement in
  [`specs/`](specs/). Start from [`specs/TEMPLATE.md`](specs/TEMPLATE.md);
  [`SPEC-001`](specs/SPEC-001-core-integrity.md) records the invariants
  already enforced.
- **Simplicity wins.** Standard library first, no speculative abstraction, new
  dependencies justified in a spec's Decision log.
- **Tests are for business-critical rules only**: requirements marked
  `Test: yes`, each test citing its ID. No coverage targets.
- New invariants go in the database. Migrations are forward-only, and audit
  digest v1 is frozen.
- [`CLAUDE.md`](CLAUDE.md) holds the full conventions, and `.claude/agents/`
  has the `spec-writer` → `work-orchestrator` → `implementer` workflow for
  Claude Code.
